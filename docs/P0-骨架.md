# P0 骨架：这一版到底有什么

一句话：**权限面的包照旧；数据面多了一个可验证的引擎、一个只打日志的 Zygisk 探针，以及一条「成对出产物」的流水线。装模块后不会改变任何应用的行为。**

## 1. 新增了什么

| 位置 | 是什么 | 现在的状态 |
|---|---|---|
| `zig/src/engine.zig` | 数据面判定引擎（朴素 C ABI，不导出 JNI 名字） | 6 个导出符号 + 7 条单测全绿 |
| `build/engine/*/libwatchcat_engine.a` | 引擎静态库（arm64-v8a / x86_64） | `build_so.py --engine` 产出，不入库 |
| `tools/probe/engine_probe.c` | ABI 探针，模拟 shim 的链接方式 | 本机与 CI 都跑，输出对得上才继续 |
| `module/` | Magisk / Vector 模块包骨架 | 已有 shim，只打日志、不注册 hook |
| `module/src/entry.cpp` | Zygisk 入口（P0 加载探针） | 只在 server 阶段动作；app 进程零开销 |
| `module/src/zygisk/zygisk.hpp` | Magisk 官方模块 API 头（**0BSD**，非 GPL） | 原样保留，不改内容 |
| `tools/build_module_native.py` | NDK 编 shim + 16KB 门禁 + 入口符号复核 | CI 里跑；本机无 NDK 就不跑 |
| `tools/build_module.py` | 打模块 zip（强制 LF、固定时间戳、可复现） | 自动把 shim 并成 `zygisk/<abi>.so` |
| `.github/workflows/build.yml` | APK 与模块包同一 commit 成对出 | 摘要里直接列两者 sha256 前 16 位 |

## 2. 引擎语义（这里定的是协议，改它等于改版本）

```
wc_engine_version()            -> 0x00020000
wc_engine_ping()               -> 0x5743
wc_engine_rule_set(slot, uid, mask) -> 0 ok / 1 slot 越界 / 2 mask 无效 / 3 系统 uid 被拒
wc_engine_rule_clear()
wc_engine_rule_count()
wc_engine_decide(uid, kind)    -> 1 给空 / 0 放行 / 2 未知 kind（调用方按放行处理）
```

三条不能动的语义：

1. **空表 = 全放行**。进程刚起、规则还没下发时，任何应用都拿到真数据。这是 L10「默认不生效」在引擎里的落点。
2. **只拦配了的 kind**。配了剪贴板不等于把应用列表也拦掉，不搞连坐（自洽原则：每个 API 各自有明确答案）。
3. **拒绝 uid < 10000**。不让规则挂到 system_server 等系统进程上——它自己被判「给空」就没人干活了。

`decide` 是纯遍历 64 格定长表，不分配内存、不加锁。system_server 里调用不会有堆抖动。

## 3. 为什么引擎出静态库

规范 L2 定的是「native 只由 Zygisk 加载」。引擎做成 `.so` 就得管搜索路径、还得防着别的进程
半路 `loadLibrary`；做成静态库由 shim 直接链进去，**16KB 对齐只需要在最终那个 shim `.so` 上验一次**，
也不会出现「两个 .so 版本不一致」这种最难查的问题。

## 4. shim 与许可证（原计划的 P0-B，已落地）

`zygisk/*.so` 由 NDK 编（Zig 自带 libc 覆盖不了 `aarch64-linux-android`，实测报错），
链接 `libwatchcat_engine.a`，只导出 `zygisk_module_entry`。验收证据是 logcat 里一行：

```
p0: system_server 内调用 Zig 引擎 ping=0x5743 version=0x00020000 pid=...
```

之前担心的 GPL 传染**不成立**：`zygisk.hpp` 文件头自带 0BSD 风格许可
（"Permission to use, copy, modify, and/or distribute ... with or without fee"），
GPL-3.0 是 Magisk 整体仓库的许可，这个公开 API 头是单独授权的。所以按原样放进仓库是干净的，
不修改内容、保留声明即可。

## 5. 怎么验这一版

```bash
py tools/build_so.py --engine              # 本机：引擎静态库 + ABI 探针
py tools/build_module_native.py            # 需要 NDK；CI 里跑（16KB + 入口符号双重门禁）
py tools/build_module.py --require-zygisk  # 出模块 zip，日志会写清包里有没有 zygisk .so

adb shell cat /data/adb/watchcat/boot.marker     # 脚本真跑了、没被 CRLF 坑
adb logcat -s WatchCat                           # 三行 p0 日志 + armed 不存在
```
